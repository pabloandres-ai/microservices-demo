[RESOLVED] GKE Boutique App CPU Starvation Outage — 2026-03-12 06:50 UTC-6

Status: RESOLVED
Duration: ~5 minutes (06:50–06:55 UTC-6)
Severity: P1 (Complete application outage)

What happened:
Commit 3a293029 deployed a misconfigured Kubernetes manifest setting productcatalogservice pod CPU limit to 1 millicore (1m) with an aggressive liveness probe (2s period, 1s timeout, 1 failure threshold). This caused the pod to fail its health check immediately, triggering a restart loop. The failure cascaded to all dependent services (frontend, checkout, payment, etc.), resulting in HTTP 500 errors for all user requests.

What we did:
1. Identified root cause within 3 minutes: CPU limit set to 1m in commit 3a293029
2. Reverted resource limits to stable configuration (CPU 1m → 500m, memory 128Mi → 512Mi)
3. Restored liveness probe to reasonable timings (period 2s → 10s, timeout 1s → 5s, failures 1 → 3)
4. Applied corrected manifests via kubectl apply
5. All 12 services reached Running state within 1 minute

Current state:
All services healthy. Productcatalogservice pod passing liveness/readiness probes consistently. Frontend HTTP 200. All microservices operational. Monitoring ongoing for 30+ minutes with no recurrence.
